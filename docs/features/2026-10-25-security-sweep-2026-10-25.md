# Feature: Security sweep, October 2026

**Branch:** security/sweep-2026-10-25
**Date:** 2026-10-25

## Summary

Bumps `certifi` from 2026.6.17 to 2026.10.19 in `uv.lock`, pins the two
actions in `dependency-review.yml` to full commit SHAs, and stops the Phase 1
`fetch_url` tool from reaching private, loopback and metadata addresses.

## Motivation

- `certifi` 2026.6.17 ships emSign root CAs whose intermediate CA keys were
  compromised (GHSA-6q48-6c7w-9gw2, PYSEC-2026-4320, CVSS 9.1). Anyone holding
  those keys can issue certificates that `httpx` trusts. 2026.10.19 is the
  first fixed version named in the advisory.
- `dependency-review.yml` was the only workflow still using mutable tags
  (`actions/checkout@v5`, `actions/dependency-review-action@v4`) and the only
  one that left the checkout token on disk.

- `phase1/agent.py` `fetch_url` fetched any URL the model chose and followed
  redirects. A fetched page can tell the model to fetch
  `http://169.254.169.254/` or a service on `localhost`, and the reply lands in
  the transcript and the LangSmith trace. The Phase 1 README already teaches
  that every tool argument is untrusted input; the tool now follows that rule.

## What changed

- `uv.lock`: `certifi` 2026.6.17 -> 2026.10.19. No other package moved.
- `.github/workflows/dependency-review.yml`: `actions/checkout` pinned to the
  same v7.0.1 SHA the other workflows use, with `persist-credentials: false`;
  `actions/dependency-review-action` pinned to the v4.9.0 SHA (what `v4`
  pointed to).

- `phase1/agent.py`: `fetch_url` accepts only http(s) URLs whose host is a
  public address (IP literal or every DNS answer `is_global`). The request goes
  to the address that was checked, with the name kept in the `Host` header and
  in TLS SNI, so certificate checks still use the name and a DNS answer that
  changes after the check (DNS rebinding) cannot reach a private address. The
  client ignores proxy environment variables (`trust_env=False`): inside an
  `HTTPS_PROXY` tunnel httpx checks the certificate against the IP, so every
  https fetch would fail. It
  no longer follows redirects; a redirect returns `HTTP 30x` plus the target
  URL, so the model's next call goes through the same check.
- `tests/test_phase1.py`: new cases for 6 refused addresses, the redirect
  hand-back, the pinned address with Host/SNI, and a DNS answer that changes
  between lookups. DNS and `httpx.Client.get` are stubbed so the suite stays
  offline.
- `phase1/README.md`: the tool list says what `fetch_url` refuses.

## Notes

- 2026.10.19 (uploaded 2026-10-20) is inside the sweep's 7-day cooldown. It is the lowest fixed
  version, so it was taken on purpose. 2026.10.18 is not fixed.
- Made with `uv lock --upgrade-package certifi==2026.10.19`, not a full
  upgrade.
