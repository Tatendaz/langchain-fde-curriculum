## Decisions

- Lowest fixed version of `certifi`, even though it is inside the 7-day
  cooldown: there is no older fixed release.
- `dependency-review-action` stays on v4 (pinned to v4.9.0) instead of moving
  to v5.
- `phase1/agent.py` `fetch_url`: first left as is (fixed prompt, local demo).
  CodeRabbit flagged it on the PR. Its claim that `main()` takes any task is
  wrong, but a fetched page can still steer the model to an internal URL, so
  it is fixed: public http(s) hosts only, no automatic redirects.
- CodeRabbit then pointed out DNS rebinding (the check and the request did
  separate lookups). The request now goes to the checked IP with `Host` and
  `sni_hostname` set to the name. Checked live: example.com over http and
  https returns 200, wrong.host.badssl.com fails the hostname check, and
  127.0.0.1 / localhost are refused.
- CodeRabbit's next review: an `HTTPS_PROXY` tunnel ignores `sni_hostname`
  (confirmed in httpcore `http_proxy.py`). Set `trust_env=False`; checked
  live with `HTTPS_PROXY` pointing at a dead port: example.com still returns 200.
- Backup review (low): an international domain name reached the Host header
  and SNI in Unicode and failed. Now uses `parsed.raw_host` (punycode); new
  test, and https://bücher.de/ checked live.
- Backup review (low): only the first resolved address was tried, so a host
  with an unreachable IPv6 answer failed. `fetch_url` now tries every checked
  address in order on `ConnectError`; new test.
